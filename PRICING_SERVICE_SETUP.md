# Automatic pricing after inventory uploads

The public GitHub Pages frontend cannot run retailer searches itself. `render.yaml` prepares a single persistent Node service with the existing app, SQLite history, background queues, bounded source requests and generated API authentication. No Wine-Searcher/Brave subscription is required. Render's service and persistent disk incur hosting charges; review its current quoted price before creating them. No paid service has been created by Codex.

1. Open the app's **Connect engine → Set up the prepared Render service**, or https://dashboard.render.com/blueprint/new?repo=https%3A%2F%2Fgithub.com%2Fsta2014%2FWine-Purchase-App . Sign in/create an account, connect GitHub and select this repository.
2. Review the service and persistent-disk charges, then create it if acceptable. Wait for its deployment to become live. The configuration builds the frontend and starts the existing Node engine; the database lives on its persistent disk.
3. In Render's service dashboard, copy the public service URL and generated `ENGINE_ACCESS_TOKEN` from Environment. In the wine app, select **Connect engine**. Enter the public URL with `/api` appended and paste the generated token into the password field. Connecting switches to the server's inventory; browser data remains separate. Export the existing engine backup first if it contains manual corrections or reviews you want to restore on the new service. Import/restore the data there, reload the supplied charts if needed, and enable only reviewed source permissions after a restore.
4. Upload the Flickinger Excel inventory while connected. The API queues searches automatically after a successful inventory import, using existing cached results and avoiding duplicate jobs. Verify progress in **Market research**; verified prices enter normal ranking as jobs complete. The buying table reloads server data every minute while no dialog is open. Research continues while the online service runs. The token lasts only for the current page session; reconnect after reloading the page.

Automatic upload research queues up to 10,000 distinct wine identities against at most five permitted sources, subject to the existing 20,000 retained-job capacity. Requests remain bounded to two concurrent jobs by default and at least five seconds per merchant request. Large inventories take time; upload success is not a claim that every wine has a price. Cache-skipped wines do not prevent later unsearched wines from being queued. Sources missing permitted access or verified product extraction remain inactive. One public retailer (JJ Buckley) is currently live-validated; broader source validation is still needed. An enabled retailer does not guarantee it stocks the same wines.

The current uploaded file contains 8,645 listings and color codes R/W/S. Header and color-code normalization, explicit inventory metadata updates, Ermitage/Hermitage and Clos du Tart aliases now produce 6,917 vintage matches with the 466 supplied assessments. Reimport keeps the same count. There is no automatic inference that every red California wine is Cabernet or every white is Chardonnay. The current red Burgundy chart covers Côte de Nuits; the current Tuscan chart covers Chianti/Chianti Classico. Other areas are intentionally left unassessed.
